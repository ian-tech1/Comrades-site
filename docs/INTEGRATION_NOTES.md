# Integration notes

- Supabase documents `createSignedUploadUrl` together with `uploadToSignedUrl`; the application should use the signed path and token/URL generated by Supabase rather than expose the service-role key to the browser. The target bucket must already exist. Source: <https://supabase.com/docs/reference/javascript/file-buckets-uploadtosignedurl>
- Safaricom describes Daraja 3.0 as the official bridge for M-PESA APIs and provides a sandbox app flow for integration testing. The M-Pesa Express response is forwarded to the merchant callback URL. Source: <https://developer.safaricom.co.ke/> and <https://developer.safaricom.co.ke/apis/MpesaExpressSimulate>

Implementation policy: Daraja consumer secrets, passkeys, callback configuration, Supabase service-role keys, administrator passwords, and session secrets remain in Vercel environment variables only. Development must not initiate an STK prompt.
